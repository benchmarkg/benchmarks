## Abstract

We describe a method for reading coverage gaps off a catalogue of benchmarks without mistaking the
catalogue's own blind spots for gaps in the fields it indexes. The grid is coarse by rule: the
<!-- gaps: axes.rows.count -->19<!-- /gaps --> domain families of the catalogue's taxonomy crossed with <!-- gaps: axes.columns.count -->13<!-- /gaps -->
capability groups, <!-- gaps: cells_total -->247<!-- /gaps --> cells. A cell counts benchmark families, not capability tags and not
editions or tasks, and it publishes four factors beside its gap score: normalised density, domain
activity, capability salience and curation confidence. The last measures how thoroughly the catalogue
itself has covered a domain. It multiplies the score, and a cell is asserted as a gap only when it clears
a confidence floor and dated surveys, accepted by a person, find it empty. Applied to the index at data
commit <!-- gaps: parameters.data_commit -->cc748aa035dd4d1fce04ee30c3d970bf87d538d3<!-- /gaps --> (dated <!-- gaps: parameters.as_of -->2026-11-25<!-- /gaps -->), which holds <!-- gaps: entries -->320<!-- /gaps --> published
entries, the matrix asserts <!-- gaps: claims_total -->0<!-- /gaps --> gaps: <!-- gaps: review_backed.families -->0<!-- /gaps --> of <!-- gaps: review_backed.of -->19<!-- /gaps -->
domain families carry a reviewer's sign-off, so every cell is refused for insufficient curation
confidence. We then work the four gaps the project's plan records as confirmed (phylogenetics, education
and tutoring, psychometric batteries for AI, and retrosynthesis) and show, for each, what the index
records at that commit and why the matrix does not assert it.

## 1. Method

### 1.1 The grid

The matrix crosses the <!-- gaps: axes.rows.count -->19<!-- /gaps --> domain families of `taxonomy/domains.yaml` (version
<!-- gaps: axes.rows.version -->0.9.0<!-- /gaps -->) with the <!-- gaps: axes.columns.count -->13<!-- /gaps --> capability groups of
`taxonomy/capability_groups.yaml` (version <!-- gaps: axes.columns.version -->0.9.0<!-- /gaps -->), <!-- gaps: cells_total -->247<!-- /gaps --> cells. Each group is
a fixed set of capability terms from `taxonomy/capabilities.yaml` (version
<!-- gaps: axes.columns.terms_version -->0.9.0<!-- /gaps -->). Every term belongs to exactly one group, and the group of an entry is
derived from the terms its curator tagged, never tagged directly (02 S4.3). The capability-groups
version is recorded on every cell, because moving a term between groups reshapes every gap claim in both
columns without changing a single benchmark record (12 S5.1).

A finer grid exists, (family, subdomain) pairs crossed with single capability terms, and the method does
not let it publish a gap claim. At the size of this catalogue most of its cells are empty by arithmetic,
so an empty fine cell is the grid's default state rather than a finding (12 S5.1). The emitter does not
compute it at all: `bench gaps --grid fine` exits with an error. This rule decides every worked example
in section 3, because all four candidate gaps are stated at a finer resolution than the coarse grid's.

### 1.2 The counting convention

Four rules decide what a number in the matrix counts.

- **One family, one entry.** A benchmark family is a named benchmark identity. Its editions, tasks,
  tracks and splits are its children, and every count the project publishes is a family count (02 S11).
  A family with many tasks and many editions is one entry.
- **Benchmarks per group, not tags.** The artifact states its own convention: "<!-- gaps: counting -->benchmarks per (primary family, capability group), not tags; terms decompose each count; secondary domains counted apart (12 S5.1-5.2)<!-- /gaps -->". An entry
  tagged with several terms of one group occupies that group's cell once, so the coarse total is not the
  row sum of a finer grid (12 S5.1).
- **Primary, secondary and subset matches are kept apart.** Every entry has exactly one primary domain.
  Its secondary domains, and any subset whose domain override puts it in another family, also match
  cells, at a lower weight (section 1.3). Each cell publishes the integer counts of the three kinds beside
  its density, and a cell's state is decided by presence at any weight (02 S11).
- **Drafts are presence, not confidence.** An entry no person has reviewed still occupies its cells,
  because dropping it would empty a cell that is in fact measured. It does not raise curation confidence
  (section 1.5).

What is counted: the <!-- gaps: entries -->320<!-- /gaps --> published entries at the data commit, that is every benchmark file
under `data/benchmarks/<family>/` outside the stubs directory.

### 1.3 Density

Per cell, density sums domain weight times quality weight over the entries that match the cell, each
entry once, at its heaviest match (12 S5.2). The domain weights are <!-- gaps: parameters.domain_weight.primary -->1.0<!-- /gaps -->
for a primary match, <!-- gaps: parameters.domain_weight.secondary -->0.5<!-- /gaps --> for a secondary one and
<!-- gaps: parameters.domain_weight.subset -->0.5<!-- /gaps --> for a subset-derived one. The quality weight is the product of
whichever multipliers apply, clamped between <!-- gaps: parameters.quality_clamp[0] -->0.5<!-- /gaps --> and
<!-- gaps: parameters.quality_clamp[1] -->1.5<!-- /gaps -->: verified against primary sources, x
<!-- gaps: parameters.quality_multipliers.verified -->1.2<!-- /gaps -->; machine-ingested, x
<!-- gaps: parameters.quality_multipliers.machine-ingested -->0.7<!-- /gaps -->; an activity signal within the last
<!-- gaps: parameters.activity_window_months -->18<!-- /gaps --> months, x <!-- gaps: parameters.quality_multipliers.active-in-18-months -->1.1<!-- /gaps -->,
or, where enough activity signals are observed and none falls inside that window, x
<!-- gaps: parameters.quality_multipliers.quiet-for-18-months -->0.8<!-- /gaps -->; a human baseline, x
<!-- gaps: parameters.quality_multipliers.human-baseline -->1.1<!-- /gaps -->; a sourced release date, x
<!-- gaps: parameters.quality_multipliers.sourced-release-date -->1.05<!-- /gaps -->.

Normalised density divides a cell's density by the densest applicable cell's. At data commit
<!-- gaps: parameters.data_commit -->cc748aa035dd4d1fce04ee30c3d970bf87d538d3<!-- /gaps -->, that cell is <!-- gaps: parameters.density_reference.family -->vision<!-- /gaps --> x
<!-- gaps: parameters.density_reference.group -->perception-space-time<!-- /gaps -->, at density <!-- gaps: parameters.density_reference.value -->29.8353<!-- /gaps -->, and the
curation confidence of <!-- gaps: parameters.density_reference.family -->vision<!-- /gaps --> beside it is
<!-- gaps: families[id=vision].curation_confidence.value -->0.0<!-- /gaps -->.

### 1.4 The four factors and the score

12 S5.3 defines the gap score as a product: <!-- quoted: _plan/12-analytics-and-trends.md -->(1 - normalised_density)<!-- /quoted -->
x domain_activity x capability_salience x curation_confidence. Every cell publishes the four factors
beside the product, never the product alone, so a reader who weighs them differently can re-derive a
ranking from the same JSON.

- **Normalised density**, section 1.3.
- **Domain activity**, the family's release velocity: of its entries with a release date, the share
  released in the <!-- gaps: parameters.velocity_window_months -->24<!-- /gaps --> months to the data commit's date. The plan also
  names publication velocity. The index holds no publication counts per family, so that half is not
  measured.
- **Capability salience**: of the entries whose primary family is another one, the share that carries a
  term of the group, which is how often the capability is measured elsewhere in the index.
- **Curation confidence**, section 1.5.

### 1.5 Curation confidence

Curation confidence is the honesty term (12 S5.3). It is computed per family and printed in this paper
beside every density figure. It is <!-- gaps: parameters.curation_confidence_weights.entry_coverage -->0.4<!-- /gaps --> times the
family's reviewed entries over the number of field-defining families expected to exist in it, capped at
one; plus <!-- gaps: parameters.curation_confidence_weights.verified_fraction -->0.3<!-- /gaps --> times the share of its entries
verified against primary sources within the last <!-- gaps: parameters.verified_within_days -->180<!-- /gaps --> days; plus
<!-- gaps: parameters.curation_confidence_weights.reviewer_signoff -->0.3<!-- /gaps --> times its reviewer sign-off, scored
<!-- gaps: parameters.reviewer_signoff_scores.none -->0.0<!-- /gaps --> for none, <!-- gaps: parameters.reviewer_signoff_scores.generalist -->0.5<!-- /gaps -->
for a generalist and <!-- gaps: parameters.reviewer_signoff_scores.domain-expert -->1.0<!-- /gaps --> for a domain expert.

Only reviewed entries count toward the first term: those at `curator-reviewed` or above on the project's
review ladder (05 S4). An agent draft no person has opened cannot raise the catalogue's confidence in
itself. The expected counts come from `taxonomy/domain-expectations.yaml`, version
<!-- gaps: parameters.expectations.version -->0.1.0<!-- /gaps -->, an estimate made on <!-- gaps: parameters.expectations.estimated_on -->2026-09-17<!-- /gaps --> and
recorded there as verified: <!-- gaps: parameters.expectations.verified -->false<!-- /gaps -->. A family that was never sized divides
by its seed target instead, and the family table in section 2 marks each such denominator
`seed_target (fallback)`.

### 1.6 When a cell is asserted

A cell is asserted as a gap only when it is the first of the three kinds of empty in 12 S5.4, "nobody
measures it". All of the following must hold:

- the family carries a reviewer's sign-off and is not under-surveyed;
- the cell is triaged applicable in `taxonomy/_triage/not-applicable.yaml`, and a person has accepted that
  triage;
- no entry matches the cell at any weight;
- dated survey notes, each accepted by a person, cover every subdomain of the family for every term of
  the group, so that the cell reads surveyed-and-empty;
- curation confidence is at least <!-- gaps: parameters.min_confidence -->0.6<!-- /gaps -->;
- other families measure the group (capability salience is positive), and the family has released
  something inside the velocity window (domain activity is positive).

Every other cell is refused, and the artifact says why for each one: the first reason in
`gap_claim_refusal`, all of them in `withheld`. An empty cell that fails a condition is the third kind of
empty, "we have not curated it yet", and stays visible as backlog rather than being published. The second
kind, a cell the taxonomy cuts badly, has no record in the index yet, so the emitter cannot see it.

### 1.7 A finding is a claim about the index at a commit

Every figure in this paper is a property of the index at one data commit, <!-- gaps: parameters.data_commit -->cc748aa035dd4d1fce04ee30c3d970bf87d538d3<!-- /gaps -->,
dated <!-- gaps: parameters.as_of -->2026-11-25<!-- /gaps -->. The matrix states an asserted gap in the same form: as of a data commit, this
index holds no benchmark in a given cell at any weight, and dated survey notes a person accepted cover
every subdomain of the family for the group. None of it is a claim that a benchmark does or does not
exist in the world. An empty cell says that the index holds none behind a survey a person accepted, and
a cell with no survey says only that the index has not looked.

## 5. Reproducing every figure

`build/` is not committed. To rebuild the artifact this paper describes and check the paper against it,
check out the data commit in a separate worktree, build there, and run the check from this checkout:

```sh
git worktree add ../gaps-at-commit <data-commit>
(cd ../gaps-at-commit && mkdir -p build/derived && uv run bench gaps --grid coarse --reviewed-only --format json > build/derived/gaps.json)
uv run python scripts/check_preprint_claims.py --preprint docs/preprints/gap-matrix.md --against ../gaps-at-commit/build/derived/gaps.json
```

where `<data-commit>` is <!-- gaps: parameters.data_commit -->cc748aa035dd4d1fce04ee30c3d970bf87d538d3<!-- /gaps -->. `scripts/check_gap_claims.py` checks the artifact
itself against the tree, and `docs/gap-matrix.md` is the reader's account of how it is computed.

`scripts/check_preprint_claims.py` accounts for every run of digits in this file. A figure of the index
is bound, in an HTML comment that does not render, to the path in gaps.json it is read from, and the
check fails unless the printed figure equals the value there; a figure off by one fails. A figure that
is not the index's, such as the plan's retrosynthesis results above, is marked as quoted with its source
file, and the check fails unless that file says it verbatim. Five narrow rules exempt the rest, each
verified against the repository: the number of a heading, a cross-reference to a numbered section of
this paper, a plan section cited in the repository's form when that section exists, a path to a file
that exists, and inline code naming a benchmark the artifact holds. Anything else with a digit in it, a
year, a date, a short commit hash or an invented figure, fails. The check also fails if a density figure
is printed without its family's curation confidence in the same row or paragraph, or if a section that
prints one does not cite the data commit.
